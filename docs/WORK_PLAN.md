## 最终产品边界

### 私聊 Bot

- 支持编号、编号前缀、演员/别名、标准标签与 `#原始话题` 的目录查询。
- 返回文字编目结果并支持回调翻页，不发送媒体文件；已收录的频道发布文字介绍会随结果显示，过长介绍会自动摘要；未识别或未收录时会给出可执行的查询示例。
- `/stats` 显示已审核媒体、编号、文件和最近更新时间；管理员额外看到待审核与重复候选汇总。
- `/系列剧情`（菜单命令 `/stories`）独立浏览系列剧情：一级显示“剧情名称【视频数】”，点击后显示该剧情关联的视频。二级视频完全复用普通搜索结果的番号、标签、简介、分页和频道跳转。
- `/新增剧情`（菜单命令 `/newstory`）仅管理员可用。先输入一级剧情名称，再点击“添加视频”进入选片状态；随后输入番号、演员、话题或前缀。可跨多次查询勾选多部视频，最后点击一次“加入已选视频”批量建立剧情—视频关联。该操作不移动、复制或删除频道资源；批量加入后一级计数自动更新。
- 指定频道的 owner/administrator 在私聊 Bot 时自动拥有管理员权限；`TELEGRAM_ADMIN_IDS` 仍可作为应急白名单兜底。
- `/duplicates` 仅管理员可用，按相同 Telegram 文件列出待核对候选和可见“删除”按钮；候选默认保留，不会自动合并或删除。
- `/delete` 与 `/duplicates` 都会打开候选按钮列表，不展示内部资源 ID。删除按钮采用两阶段操作：先点“删除”，再点“确认删除此条”；取消或未进行第二次确认时记录保持不变。当前频道候选会先删除对应频道消息、成功后才删除索引；旧频道遗留候选会明确标注为“仅删除目录”，确认后只清除本目录记录，绝不操作旧频道原消息。所有完成操作均写入审计。
- `/index` 用于跳转频道索引；`/refresh` 仅管理员可用，用于刷新置顶索引。

### Telegram 频道

- 频道内容保留原始媒体和 Bot 维护的置顶索引消息。
- 新媒体会登记标题、编号、演员、话题、Telegram 文件标识和消息映射。
- 未知或歧义标签保留为自由话题；未知演员和歧义演员别名进入审核队列。
- 原视频不做字幕修改、复制替换、删除或重发。
- 审核通过的入库记录可触发置顶索引刷新；索引过长时自动分页。

## 当前可维护项

- 审核结果保存在 D1 的 `review_items` 中；审核接口只保存处理记录与 `config_proposal`。
- 规则修改在 Git 分支中完成，不使用 `review-decisions.json` 或自动生成配置文件。
- 任何 `config/` 变化都必须提升 `config/version.json` 的发布版本。
- 本地与 CI 共用 `npm run check`：配置校验、别名检查、版本单调性、测试、manifest 构建和 Worker 干运行都由该命令覆盖。

## 已知限制

- 公开 HTTP 搜索仅返回 `approved` 内容；待审核项需通过受保护的审核接口读取和处理。
- 标签分类字段仅为兼容保留；当前运行时不自动选定一级分类。
- Telegram 原生 hashtag 只能检索消息本身已有的标签。由于原视频不做修改，置顶索引中的标签不保证能直接定位到旧转发视频。
